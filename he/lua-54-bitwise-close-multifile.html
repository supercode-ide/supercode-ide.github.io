02 יכולות ליבה

כל חידושי השפה של Lua 5.3 ו-5.4 המודרנית, אופליין

כתבו קוד Lua 5.4 עדכני ומדויק וחבילות מרובות תיקיות ללא מעקפים של שגיאות תחביר.

02.1

שלמים 64-bit נייטיב, חילוק // ואופרטורים בינאריים

עבדו ישירות עם bitmasks, דגלים, hashes וקואורדינטות אריחים בעזרת &, |, ~ (XOR/NOT), <<, >> וחילוק שלמים // — בגיבוי מספרים שלמים 64-bit מדויקים במקום קירובי float.

& | ~ << >> · חילוק שלמים // · math.type() 64-Bit
02.2

<const> בזמן קומפילציה וניקוי <close> מבוסס Scope

אכפו משתנים מקומיים קבועים בזמן קומפילציה עם <const> וחברו מתודות-על __close דטרמיניסטיות דרך <close>, כך שקבצים פתוחים, נעילות ושאילתות SQLite ישוחררו אוטומטית ביציאה מ-scope או בשגיאה.

local x <const> · local f <close> · __close RAII
02.3

string.pack / unpack בינארי ו-utf8 מובנה

קודדו ופיענחו מבנים בינאריים עם מפרטי endianness דרך string.pack, string.unpack ו-string.packsize, ורוצו בבטחה על מחרוזות Unicode רב-לשוניות עם utf8.codes, utf8.len ו-utf8.char.

string.pack / unpack · utf8.codes · GC דורי
02.4

05 שאלות ותשובות

שאלות נפוצות

שאלות על אופרטורים בינאריים ב-Lua 5.4, משתני `<close>` ו-`require()` מרובה תיקיות ב-Android.

למה `//` ו-`&` זורקים שגיאות תחביר באפליקציות Lua אחרות ל-Android?+
אפליקציות Lua ותיקות רבות למובייל מסתמכות על LuaJ, פורט Java שנעצר סביב Lua 5.2 לפני שמספרים שלמים 64-bit נייטיב, חילוק שלמים `//` ואופרטורים בינאריים הוצגו ב-Lua 5.3/5.4. SuperCode מריצה Lua 5.4.7 נייטיב אמיתי.
איך עובד `require()` מרובה קבצים בלי להגדיר `LUA_PATH`?+
SuperCode מגדירה אוטומטית את `package.path` כך שיחפש בשורש הפרויקט וגם ב-`src/`, `lib/`, `modules/`, `core/` ו-`utils/` עבור `?.lua` ו-`?/init.lua` — ואף מסנכרנת לשוניות פתוחות שלא נשמרו לפני ההרצה.
מה קורה אם לוחצים Run בזמן עריכת `lib/math_ext.lua` במקום `main.lua`?+
אם הקובץ הפעיל מחזיר טבלת מודול (`return M`) וקיים קובץ `main.lua` או `init.lua` בשורש הפרויקט, SuperCode מריצה אוטומטית את סקריפט הכניסה כדי שלא תצטרכו לעבור הלוך ושוב בין לשוניות.
האם `<close>` של Lua 5.4 עובד גם כשנזרקת שגיאה בתוך בלוק?+
כן. בדיוק כמו ב-Lua 5.4.7 תקני לדסקטופ, כל משתנה מקומי שמסומן כ-`<close>` מפעיל את מתודת-העל `__close(self, err)` של ה-metatable שלו בצורה דטרמיניסטית, בין אם הבלוק מסתיים כרגיל ובין אם הוא יוצא דרך `error()`.
