03 SCHRITT-FÜR-SCHRITT-ANLEITUNG

Komplette 6-Schritte-Anleitung: Git in der SuperCode IDE nutzen

Folge diesem exakten Ablauf in SuperCode, um direkt vom Smartphone oder Tablet aus zu klonen, Branches anzulegen, Diffs zu prüfen, zu mergen und zu pushen.

STEP 01 Menu -> Git Controls -> Clone

Remote-Repo klonen oder lokales Projekt einbinden

Füge deine HTTPS-URL (z. B. https://github.com/user/repo.git) und optional dein PAT-Token ein und tippe auf KLONEN — oder wähle Vorhandenes Repo einbinden bei bestehenden .git-Ordnern.

STEP 02 Time Machine -> Branch ▾

Feature-Branch wechseln oder neu anlegen

Öffne die Git-Zeitmaschine und tippe oben auf die Branch-Auswahl, um den Zweig zu wechseln oder per + Neuen Branch erstellen… (z. B. feature/mobile-ui) einen geprüften Branch anzulegen.

STEP 03 Editor Tabs -> Save / Edit

Mehrdatei-Code mit voller IDE-Intelligenz bearbeiten

Ändere, formatiere und teste deinen Code offline. Selbst wenn du vergisst, einen Tab zu speichern, schreiben Git-Aktionen offene Änderungen vor der Ausführung automatisch auf den Speicher.

STEP 04 Git Dashboard -> Pull

Remote-Änderungen des Teams sicher abrufen

Tippe vor dem Push auf Pull. Ungesicherte lokale Änderungen werden automatisch per Stash geparkt und wiederhergestellt; offene Tabs aktualisieren sich ohne Verlust der Cursorposition.

STEP 05 Open Conflict Resolver

Etwaige Merge-Kollisionen visuell auflösen

Treten überlappende Änderungen auf, öffne den Konfliktlöser, vergleiche Lokal- und Remote-Blöcke nebeneinander, wähle Aktuell / Eingehend / Beide behalten und tippe auf Lösungen anwenden.

STEP 06 Commit & Push

Geänderte Dateien prüfen, Nachricht schreiben & pushen

Kontrolliere die [M]/[A]/[D]-Markierungen in den ausstehenden Änderungen, bestätige Autorenidentität sowie Commit-Nachricht und tippe auf COMMIT zum Stagen, Committen und Pushen.

Automatische Bereinigung verwaister index.lock-Dateien · Unterstützt lokale Offline-Commits App-Guide

05 FRAGEN & ANTWORTEN

Häufig gestellte Fragen (FAQ)

Praxisnahe Antworten zu GitHub Personal Access Tokens, privaten Repositories, Merge-Konflikten und der Commit-Historie.

Wie authentifiziere ich mich bei privaten Repositories auf GitHub, GitLab oder Gitee?+
Erstelle auf GitHub/GitLab/Gitee ein HTTPS Personal Access Token (PAT) mit repo-Berechtigung und füge es beim Klonen, Commit & Push oder Pull in das Token-Feld ein. SuperCode speichert es verschlüsselt für künftige Vorgänge.
Was passiert, wenn ich auf Pull tippe, während noch ungespeicherte Tabs oder uncommittete Änderungen vorliegen?+
SuperCode schreibt ungespeicherte Tabs zuerst auf den Datenträger, sichert deine lokalen Änderungen per Auto-Stash, lädt die neuesten Remote-Commits herunter, spielt deine Änderungen wieder ein und aktualisiert offene Tabs an deiner exakten Zeile.
Wie sehe ich mir Änderungen eines früheren Commits an oder setze einen Zweig zurück?+
Öffne im Git-Dashboard die Git-Zeitmaschine und tippe auf einen beliebigen Commit. Wähle Code-Änderungen anzeigen (Commit-Diff) für einen farbigen Unified Diff, Checkout (Nur Lesen) zur sicheren Ansicht oder Hard Reset zum Zurücksetzen.
Kann ich Änderungen auch offline ohne Internetverbindung committen?+
Ja! Stagen, lokale Commits, das Erstellen von Branches, die Historienprüfung, Unified Diffs und die Konfliktlösung funktionieren komplett offline; pushe deine lokalen Commits einfach später bei bestehender Verbindung.
