05 QUESTIONS & ANSWERS

Frequently Asked Questions

Questions about Lua 5.4 bitwise operators, `<close>` variables, and multi-folder `require()` on Android.

Why do `//` and `&` throw syntax errors in other Android Lua apps?+
Many older mobile Lua apps rely on LuaJ, a Java port frozen around Lua 5.2 before native 64-bit integers, `//` floor division, and bitwise operators were introduced in Lua 5.3/5.4. SuperCode runs genuine native Lua 5.4.7.
How does multi-file `require()` work without setting `LUA_PATH`?+
SuperCode automatically configures `package.path` to search your project root as well as `src/`, `lib/`, `modules/`, `core/`, and `utils/` for both `?.lua` and `?/init.lua` — and even syncs unsaved open tabs before running.
What happens if I press Run while editing `lib/math_ext.lua` instead of `main.lua`?+
If the active file returns a module table (`return M`) and a `main.lua` or `init.lua` exists in your project root, SuperCode automatically runs the entry script so you don't have to switch tabs back and forth.
Does Lua 5.4 `<close>` work if an error is raised inside a block?+
Yes. Just like standard desktop Lua 5.4.7, any local variable marked `<close>` invokes its metatable's `__close(self, err)` metamethod deterministically whether the block exits normally or unwinds via `error()`.
