02 КЛЮЧОВІ МОЖЛИВОСТІ

Ергономіка десктопних Python-проєктів, переосмислена для сенсорного екрана

Кожна деталь резолвера робочого простору Python у SuperCode створена, щоб прибрати рутину роботи з файлами на смартфоні.

02.1

Розумний вибір точки входу з будь-якої відкритої вкладки

Редагуєте `services/ledger.py` чи `models/user.py` без скрипту запуску? Натискання Run автоматично знаходить корінь проєкту (`pyproject.toml`, `requirements.txt`, `.git`) і запускає `main.py`, `app.py`, `run.py` або `src/main.py`.

Редагування модуля -> Натиск Run -> Запуск main.py
02.2

Оверлей незбережених вкладок у пам’яті та простори імен PEP 420

Змініть три відкриті `.py`-вкладки й одразу тисніть Run — SuperCode накладає незбережені буфери редактора в пам’яті, не засмічуючи теки `src/` порожніми файлами `__init__.py`.

Миттєвий запуск · Неявні пакети просторів імен PEP 420
02.3

Справжній інтерактивний input() і двопанельна консоль з [EOF]

Тестуйте CLI-програми з послідовними викликами `input()` та `sys.stdin.readline()`. Консоль автоматично пристиковується знизу на телефонах або ділить екран 55%/45% на планшетах із миттєвою зупинкою.

Неблокуюча черга Stdin · Сигнал [EOF] · Поділ 55:45
02.4

Офлайн AST-автодоповнення, форматер PEP 8 і Радар помилок

Введіть `.` після класів чи модулів для субмілісекундних офлайн-підказок AST, вирівнюйте відступи за PEP 8 в один дотик і виявляйте змішані табуляції/пробіли (`TabError`) чи пропущені двокрапки через Радар помилок до запуску.

Рушій областей AST · PEP 8 в 1 дотик · Радар TabError
02.5

Автономний Visual Git і Машина часу на 120 комітів

Клонуйте приватні репозиторії GitHub/GitLab по HTTPS PAT, створюйте гілки фіч, переглядайте підсвічені diff-и, візуально вирішуйте конфлікти злиття й пуште коміти без виходу з редактора.

Клон · Гілки · Візуальний Merge · Коміт і Пуш
02.6

Нечіткий пошук по 50 000 файлів і глобальний Regex-пошук

Перестрибуйте до будь-якого `.py`-модуля у величезних монорепах за мілісекунди через нечіткий пошук або рефакторьте назви функцій по всьому проєкту потоковим пошуком і заміною з Regex.

03 ПОКРОКОВИЙ ПРОЦЕС

Як клонувати, рефакторити, тестувати й пушити Python-репозиторій на Android

Повний цикл інженерії програмного забезпечення прямо на смартфоні або планшеті Android.

STEP 01 Git Clone / Open Folder

Клонуйте репозиторій GitHub або відкрийте локальне дерево проєкту

Клонуйте через HTTPS Personal Access Token або відкрийте будь-яку папку в пам’яті пристрою — зайві `.git`, `venv` і `__pycache__` автоматично ігноруються при скануванні.

STEP 02 Multi-Tab Edit + PEP 8

Редагуйте модулі з AST-доповненням і панеллю на 21 символ

Свайпайте вгору на 21-клавішній панелі символів для `:`, `->`, `_`, `()`, `[]` та `INDENT` і натискайте Форматувати для охайного 4-пробільного PEP 8.

STEP 03 Run ▶ / unittest

Запускайте головні скрипти або набори юніт-тестів офлайн

Виконуйте `main.py` чи тести `unittest` офлайн із миттєвим мілісекундним таймінгом і клікабельною навігацією по стек-трейсу.

STEP 04 Git Time Machine -> Push

Переглядайте уніфіковані diff-и, комітьте та пуште в апстрім

Перевіряйте покрокові зміни в Git Машині часу, індексуйте файли й чисто пуште назад на GitHub, GitLab чи Bitbucket.

05 ПИТАННЯ ТА ВІДПОВІДІ

Часті запитання

Запитання щодо структури `src/`, відносних імпортів, `unittest` та інтеграції Git для Python на Android.

Що станеться, якщо натиснути Run під час редагування допоміжного модуля, наприклад `utils/helpers.py`?+
Якщо `helpers.py` лише визначає функції чи класи без коду запуску на верхньому рівні, SuperCode автоматично знаходить головний скрипт проєкту (`main.py`, `app.py`, `run.py`, `__main__.py` або `src/main.py`) і запускає весь застосунок.
Чи підтримує SuperCode синтаксис Python 3.12, як-от `match/case` та псевдоніми `type`?+
Структурний `match/case` і `tomllib` працюють офлайн у Python 3.11+, а файли з узагальненим синтаксисом псевдонімів `type` за PEP 695 автоматично активують підтримку Python 3.12.
Чи потрібен `__init__.py` у кожній теці для роботи імпортів між папками?+
Ні. SuperCode дотримується неявних пакетів просторів імен PEP 420 і чисто монтує корінь проєкту, не додаючи зайвих файлів `__init__.py` у ваш репозиторій.
Чи можу я клонувати приватні репозиторії GitHub і запускати їхні Python-тести офлайн?+
Так. Клонуйте через HTTPS + Personal Access Token у Visual Git, одноразово встановіть пакетно `requirements.txt`, а далі редагуйте й запускайте тести `unittest` повністю офлайн будь-де.
