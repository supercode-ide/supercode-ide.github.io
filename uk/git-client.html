02 КЛЮЧОВІ МОЖЛИВОСТІ

Усі ключові операції Git — спроєктовані спеціально для сенсорного керування

03 ПОКРОКОВИЙ ПРОЦЕС

Повний посібник із 6 кроків: як працювати з Git у SuperCode IDE

Дотримуйтеся цього сценарію в SuperCode, щоб клонувати, розгалужувати, переглядати diff, зливати й пушити зі смартфона чи планшета.

STEP 01 Menu -> Git Controls -> Clone

Клонуйте віддалений репозиторій або підключіть локальний проєкт

Вставте HTTPS URL (напр., https://github.com/user/repo.git) і за потреби токен PAT, потім натисніть CLONE — або виберіть Підключити наявний репозиторій, якщо в теці вже є каталог .git.

STEP 02 Time Machine -> Branch ▾

Перемкніть або створіть гілку для нової фічі

Відкрийте Git Time Machine, торкніться верхнього перемикача гілок для переходу або натисніть + Створити нову гілку… (напр., feature/mobile-ui) з автоматичною перевіркою коректності назви.

STEP 03 Editor Tabs -> Save / Edit

Редагуйте код у кількох файлах із повним інтелектом IDE

Змінюйте, форматуйте й тестуйте код офлайн. Навіть якщо ви забули зберегти відкриту вкладку, Git-операції автоматично запишуть незбережені зміни на диск перед запуском.

STEP 04 Git Dashboard -> Pull

Безпечно завантажуйте оновлення команди через Pull

Натискайте Pull перед відправленням змін. Незакомічені локальні правки автоматично потраплять у stash і відновляться, а відкриті вкладки оновляться без втрати позиції курсора.

STEP 05 Open Conflict Resolver

Вирішуйте будь-які колізії злиття візуально

У разі накладання правок натисніть Відкрити редактор конфліктів, порівняйте локальний і віддалений блоки поруч, виберіть Поточна / Вхідна / Обидві та натисніть Застосувати рішення.

STEP 06 Commit & Push

Перевірте змінені файли, напишіть повідомлення & виконайте Push

Перегляньте значки [M]/[A]/[D] у списку очікуваних змін, перевірте дані автора й текст коміту та натисніть COMMIT для індексації, коміту й відправлення в origin.

Автовідновлення завислих index.lock · Підтримка локальних комітів офлайн Посібник

05 ПИТАННЯ ТА ВІДПОВІДІ

Часті запитання

Практичні відповіді про токени GitHub PAT, приватні репозиторії, конфлікти злиття та історію комітів.

Як пройти автентифікацію для приватних репозиторіїв GitHub, GitLab або Gitee?+
Створіть HTTPS Personal Access Token (PAT) із правами repo на GitHub/GitLab/Gitee та вставте його в поле Token під час Clone, Commit & Push або Pull. SuperCode надійно збереже токен, тож вводити його щоразу не доведеться.
Що станеться, якщо натиснути Pull за наявності незбережених вкладок або незакомічених змін?+
SuperCode спершу збереже незбережені вкладки на диск, автоматично сховає у stash незакомічені відстежувані зміни, завантажить останні віддалені коміти, повторно застосує ваші локальні правки та перезавантажить відкриті вкладки точно на рядку з курсором.
Як переглянути зміни в попередньому коміті або відкотитися назад?+
Відкрийте Git Time Machine на панелі Git і торкніться будь-якого коміту на часовій шкалі. Виберіть Переглянути зміни коду (Commit Diff) для кольорового Unified Diff, Checkout (Тільки перегляд) для безпечного огляду знімка або Hard Reset для відкату гілки.
Чи можна робити коміти офлайн без підключення до інтернету?+
Так! Індексація, локальні коміти, створення гілок, перегляд історії, Unified Diff і вирішення конфліктів повністю працюють офлайн; ви зможете запушити локальні коміти в origin, щойно з'явиться зв'язок.
