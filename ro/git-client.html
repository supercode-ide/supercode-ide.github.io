03 FLUX DE LUCRU PAS CU PAS

Ghid complet în 6 pași: Cum folosești Git în SuperCode IDE

Urmează acest flux exact în SuperCode pentru a clona, crea branch-uri, compara diff-uri, face merge și push de pe telefon sau tabletă.

STEP 01 Menu -> Git Controls -> Clone

Clonează un repo remote sau montează un proiect local

Lipește URL-ul HTTPS (ex. https://github.com/user/repo.git) și tokenul PAT opțional, apoi apasă CLONE — sau atinge Mount Existing Repo dacă folderul conține deja un director .git.

STEP 02 Time Machine -> Branch ▾

Schimbă sau creează un branch de funcționalitate

Deschide Git Time Machine și atinge selectorul de branch de sus pentru a schimba branch-ul sau atinge + Create New Branch… (ex. feature/mobile-ui) cu validare automată a numelui de branch.

STEP 03 Editor Tabs -> Save / Edit

Editează cod multi-fișier cu inteligența completă a IDE-ului

Modifică, formatează și testează codul offline. Chiar dacă uiți să salvezi o filă deschisă, operațiunile Git salvează automat pe disc filele modificate înainte de execuție.

STEP 04 Git Dashboard -> Pull

Trage în siguranță actualizările echipei de pe remote

Atinge Pull înainte de push. Modificările locale fără commit sunt puse în stash și restaurate automat, iar filele deschise se reîmprospătează pe loc fără a pierde poziția cursorului.

STEP 05 Open Conflict Resolver

Rezolvă vizual orice coliziune de merge

Dacă apar modificări suprapuse, atinge Open Conflict Resolver, compară blocurile Local vs Remote alăturat, alege Keep Current / Incoming / Both și apasă Apply Resolutions.

STEP 06 Commit & Push

Verifică fișierele în așteptare, scrie mesajul & fă Push

Verifică etichetele [M]/[A]/[D] în lista Pending Changes, confirmă identitatea autorului și mesajul de commit, apoi atinge COMMIT pentru stage, commit și push către origin.

05 ÎNTREBĂRI ȘI RĂSPUNSURI

Întrebări frecvente

Răspunsuri practice despre Personal Access Tokens GitHub, repo-uri private, conflicte de merge și istoricul commit-urilor.

Cum mă autentific pe repository-uri private GitHub, GitLab sau Gitee?+
Generează un HTTPS Personal Access Token (PAT) cu permisiuni de repo pe GitHub/GitLab/Gitee și lipește-l în câmpul Token la Clone, Commit & Push sau Pull. SuperCode îl salvează securizat ca să nu îl reintroduci de fiecare dată.
Ce se întâmplă dacă apăs Pull când am file nesalvate sau modificări fără commit?+
SuperCode scrie mai întâi pe disc filele nesalvate, pune automat în stash modificările urmărite fără commit, trage ultimele commit-uri de pe remote, reaplică munca locală și reîncarcă filele deschise exact la linia cursorului.
Cum văd ce s-a schimbat într-un commit anterior sau cum revin la o versiune?+
Deschide Git Time Machine din panoul Git și atinge orice commit din cronologie. Alege View Code Changes (Commit Diff) pentru un Unified Diff colorat, Checkout (View Only) pentru a inspecta în siguranță acel snapshot sau Hard Reset pentru a derula înapoi branch-ul.
Pot face commit offline când nu am conexiune la internet?+
Da! Staging-ul, commit-urile locale, crearea de branch-uri, inspectarea istoricului, Unified Diff-urile și rezolvarea conflictelor funcționează complet offline; fă push către origin imediat ce te reconectezi.
