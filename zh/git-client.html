03 分步实操使用方法

完整 6 步实操指南：如何在 SuperCode IDE 中使用 Git

跟随这套标准触控工作流，在手机或平板上行云流水般完成克隆、建分支、编码、拉取、解冲突与推送。

STEP 01 菜单 -> Git 版本控制 -> 克隆

克隆远程仓库或一键挂载本地已有 Git 工程

粘贴 HTTPS 仓库地址（如 GitHub 或 Gitee 链接）及可选 PAT 令牌并点击克隆；若本地文件夹已包含 .git 目录，直接点击「挂载已有仓库」即可。

STEP 02 提交时光机 -> 分支选择 ▾

切换分支或创建全新特性开发分支

打开 Git 时光机并点击顶部分支下拉框，即可一键切换现有分支，或点击「+ 新建分支…」（如 feature/mobile-ui，自带合法分支名校验）。

STEP 03 编辑器多标签 -> 编码调试

使用完整离线 IDE 智能补全修改并测试多文件代码

离线编写、一键格式化并运行验证业务代码。即便偶尔忘记手动点击保存，后续 Git 操作也会在运行前自动帮您将脏标签页安全落盘。

STEP 04 Git 仪表盘 -> 拉取 (Pull)

推送前安全同步团队最新远端提交

推送代码前先点击 Pull。本地尚未提交的修改会被自动暂存并在拉取后无缝还原，当前打开的代码标签页也会保留原光标位置静默刷新。

STEP 05 打开冲突解决器

通过可视化对比卡片轻松化解代码合并冲突

若多人修改同一处触发冲突，点击「打开冲突解决器」，并排比对本地代码块与远端传入块，点选保留策略后点击「应用解决方案」即可。

STEP 06 提交并推送 (Commit & Push)

核对变更文件清单、填写提交说明并推送到远端

在待提交列表中核验 [M]/[A]/[D] 变更状态，确认作者署名与 Commit Message，轻点提交即可一气呵成完成暂存、本地提交与远端推送。

05 常见问答

常见问题解答 (FAQ)

关于 GitHub / Gitee 个人访问令牌（PAT）登录、拉取防冲突、回滚历史版本与离线提交的实用解答。

在手机上如何安全登录并拉取推送 GitHub、GitLab 或国内 Gitee（码云）的私有仓库？+
只需在 GitHub / GitLab / Gitee 网页个人设置中生成一枚勾选仓库读写权限（repo）的 HTTPS 个人访问令牌（PAT），在首次克隆、拉取或推送时粘贴填入 Token 栏即可。SuperCode 会将其加密持久化保存，后续一键推送无需重复输入。
如果我有打开着还没保存的文件或没提交的代码，直接点 Pull 拉取会丢代码吗？+
绝不会！SuperCode 会先自动将所有已修改的编辑器标签页落盘保存，随后自动暂存您未提交的本地改动、拉取远端新提交、重新叠加上您的本地工作，并在保留当前光标精确行号的前提下刷新标签页。
如何查看某次历史提交到底改了哪几行代码，或者将代码回退到旧版本？+
在 Git 仪表盘打开「Git 提交时光机」，点击时间轴上的任意一条提交记录：选择「查看代码变更（Commit Diff）」即可打开红绿双色高亮对比视图；选择「只读检出」可安全浏览历史快照；选择「硬重置（Hard Reset）」即可经确认后将分支回退至该节点。
在飞机或地铁等没有网络的环境下，可以使用 Git 提交代码吗？+
完全可以！暂存变更、提交到本地仓库、新建切换分支、浏览提交时光机彩色 Diff 以及可视化解决合并冲突全部支持 100% 离线运行；等恢复网络连接后，再一键 Push 推送至远端即可。
