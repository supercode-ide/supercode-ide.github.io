05 常见问答

常见问题解答 (FAQ)

解答 Android 上常见的 `undefined reference` 链接报错、`#include` 路径、Makefile 与 CMake 相关问题。

为什么在别的 Android C 应用里写 `#include "helper.h"` 会报 `undefined reference`？+
单文件手机应用只会把当前打开的那一个文件交给编译器，根本不会去链接 `helper.c`。SuperCode 会扫描你的工程目录（包括所有 `src/` 和 `include/` 子目录），将 `helper.c` 与 `main.c` 一同编译并自动完成目标文件链接。
小型 C 语言项目必须手写 `CMakeLists.txt` 或 `Makefile` 吗？+
完全不用。如果目录里没有 `CMakeLists.txt` 或 `Makefile`，SuperCode 的零配置 `#include "..."` 依赖追踪器会自动发现并链接全部 `.c` 与 `.h` 文件；而当项目包含 `CMakeLists.txt` 或 `Makefile` 时，SuperCode 则会严格按其目标图构建。
如果我在打开的 `.h` 标签页里刚改了代码还没点保存，直接运行会生效吗？+
会生效。SuperCode 会自动将编辑器中未保存的内存缓冲叠加到工作区构建快照上，因此所有打开的 `.h` 和 `.c` 标签页修改都会即时参与编译。
工作区里同时存在两个不同的 `main()` 测试程序时，SuperCode 怎么处理？+
如果你在包含自身 `main()` 的文件中点击运行，该文件中的 `main()` 优先执行；如果你是在共用的 `.h` 头文件中点击运行，SuperCode 会结合 `CMakeLists.txt`/`Makefile` 目标以及局部 `#include` 依赖边精准匹配对应可执行目标，避免多重定义符号冲突。
