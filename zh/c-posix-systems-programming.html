05 常见问答

常见问题解答 (FAQ)

关于 Android 上操作系统课程实验、`pthread` 链接、`fork()` 与 Socket 编程的常见问题。

`<unistd.h>`、`<dirent.h>` 和 `<getopt.h>` 可以完全离线编译吗？+
可以。`unistd.h`、`fcntl.h`、`dirent.h`、`poll.h`、`regex.h`、`fnmatch.h`、`getopt.h`、`sys/stat.h`、`sys/time.h`、`signal.h` 和 `stdatomic.h` 等核心 POSIX 头文件均已直接内置于离线 C17 sysroot 中。
使用 `<pthread.h>` 或 `<semaphore.h>` 时需要手动添加 `-pthread` 参数吗？+
不需要。SuperCode 会自动识别 `<pthread.h>` 和 `<semaphore.h>`，并自动为 POSIX 云端 C 编译器传入 `-pthread -lm`，无需任何构建参数配置。
为什么 `fork()`、`pipe()` 和 `<sys/socket.h>` 需要走 POSIX 云端 C 层级运行？+
现代 Android 的 SELinux 安全策略会拦截应用沙箱内的子进程 `fork()` 树与底层 Socket 绑定。将这些特定实验路由至隔离的 Linux 容器，可让操作系统教材中的标准代码无需修改即可直接运行。
如果我的多文件 `pthread` 项目在 `worker.h` 中拼写出错，报错能定位到正确的文件和行号吗？+
可以。SuperCode 的多文件打包器会为每个引入的头文件和 `.c` 编译单元生成标准 C `#line` 标记，因此诊断信息会 1:1 精准定位到 `worker.h` 及其准确行号。
