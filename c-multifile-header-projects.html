05 QUESTIONS & ANSWERS

Frequently Asked Questions

Common questions on `undefined reference` errors, `#include` paths, Makefiles, and CMake on Android.

Why do other Android C apps give `undefined reference` when I `#include "helper.h"`?+
Single-file mobile apps only pass the active file to the compiler and never link `helper.c`. SuperCode scans your folder (and any `src/` or `include/` subdirectories), compiles `helper.c` alongside `main.c`, and links all object files together automatically.
Do I have to write a `CMakeLists.txt` or `Makefile` for small C projects?+
Not at all. If no `CMakeLists.txt` or `Makefile` is present, SuperCode's zero-config `#include "..."` dependency crawler discovers and links your `.c` and `.h` files automatically. When a `CMakeLists.txt` or `Makefile` is present, SuperCode respects its target graph.
What if my project has unsaved edits in an open `.h` tab when I press Run?+
SuperCode overlays live unsaved editor buffers onto the workspace build snapshot automatically, so edits across open `.h` and `.c` tabs are always reflected immediately.
How does SuperCode handle a workspace that contains two separate `main()` test programs?+
If you run a file that defines its own `main()`, that `main()` wins. If you run from a shared `.h` header, SuperCode checks `CMakeLists.txt`/`Makefile` targets and local `#include` edges to pick the matching executable without duplicate-symbol clashes.
