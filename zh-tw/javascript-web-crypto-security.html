02.1

內建 W3C crypto.subtle 與 Node.js node:crypto

同時使用 `globalThis.crypto.subtle`（`crypto.webcrypto`）與經典 Node 後端呼叫（`import crypto from 'node:crypto'`）編寫跨執行時期安全模組 — 無須 polyfill 套件或外部 npm 安裝。

crypto.subtle · crypto.webcrypto · node:crypto
02.2

AES-128/192/256 驗證加密（GCM、CBC、CTR）

透過 `createCipheriv` / `createDecipheriv` 或 `crypto.subtle.encrypt` / `decrypt` 離線加解密 Payload。完整支援 `getAuthTag()` 與 `setAuthTag()`，精確驗證 AEAD 密文完整性。

aes-256-gcm · aes-256-cbc · aes-256-ctr · AuthTag
02.3

SHA-256/512 摘要、HMAC Webhook 與 timingSafeEqual

驗證 GitHub/Stripe 風格 HMAC-SHA256 Webhook 標頭，使用 `base64url` Buffer 打造零相依 HS256/HS512 JWT 驗證器，並透過 `crypto.timingSafeEqual(a, b)` 防範計時旁路攻擊。

createHash · createHmac · base64url · timingSafeEqual
02.4

PBKDF2 金鑰延展與 CSPRNG 隨機數

使用 `pbkdf2`、`pbkdf2Sync` 或 `subtle.deriveBits` 從密碼片語衍生高強度 256 位元金鑰，並透過 `randomBytes()`、`getRandomValues()` 與 `randomUUID()` 產生密碼學安全鹽值、IV Nonce 及 v4 識別碼。

pbkdf2Sync · randomBytes · getRandomValues · randomUUID
02.5

100% 實體隔離稽核敏感 Token 與 Payload

05 常見問答

常見問題

關於離線 Web Crypto、`node:crypto` 加密演算法、JWT 驗證與密鑰安全的常見解答。

為什麼 `crypto.subtle` 在基礎 Android WebView 應用程式中常會失敗，但在 SuperCode 中卻能離線運作？+
瀏覽器會在不安全的 `file://` 頁面限制 `window.crypto.subtle`。SuperCode 的獨立 JavaScript Worker 在離線環境中原生提供 `globalThis.crypto.subtle`（`crypto.webcrypto`）與 `node:crypto`，完全不受安全內容（Secure Context）限制。
離線環境支援哪些 AES 加密模式與摘要演算法？+
支援 `aes-128`、`aes-192` 與 `aes-256` 的 `GCM`（含 16 位元組驗證標籤）、`CBC` 及 `CTR` 模式，並同時支援 `SHA-1`、`SHA-256`、`SHA-384`、`SHA-512` 與 `MD5` 雜湊及 HMAC。
`Buffer.toString('base64url')` 是否可用於建構與驗證 JWT？+
可以！SuperCode 的 `Buffer` 實作開箱即支援 `utf8`、`hex`、`base64` 與 RFC 4648 `base64url` 編解碼 — 讓撰寫零相依的 JWT 與 OAuth PKCE `S256` 腳本變得輕而易舉。
執行 `node:crypto` 時，會有任何金鑰或 Payload 透過網路傳輸嗎？+
絕不會。所有 `node:crypto` 與 `crypto.subtle` 運算皆 100% 在你的 Android 裝置本機執行，即使完全關閉 Wi-Fi 與行動數據也能正常運作。
