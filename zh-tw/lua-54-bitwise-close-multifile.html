02 核心能力

完整離線支援 Lua 5.3 與 5.4 現代語言特性

撰寫符合標準規格的現代 Lua 5.4 程式碼與多目錄套件，再也不必為了避開語法錯誤而妥協。

02.1

原生 64 位元整數、// 除法與位元運算子

直接使用 &、|、~（XOR/NOT）、<<、>> 與 // 整數無條件捨去除法來處理位元遮罩、旗標、雜湊與圖磚座標 — 由精確的 64 位元有號整數驅動，而非浮點數近似值。

& | ~ << >> · // 整數除法 · 64 位元 math.type()
02.2

編譯期 <const> 與作用域 <close> 自動清理

透過 <const> 在編譯期強制鎖定不可變區域變數，並利用 <close> 綁定具確定性的 __close 元方法，讓開啟的檔案、鎖定資源與 SQLite 陳述式在離開作用域或發生錯誤時自動釋放。

local x <const> · local f <close> · __close RAII
02.3

二進位 string.pack / unpack 與內建 utf8

使用 string.pack、string.unpack 與 string.packsize 搭配位元組序格式編解碼二進位結構，並透過 utf8.codes、utf8.len 與 utf8.char 安全走訪多國語系 Unicode 字串。

string.pack / unpack · utf8.codes · 分代 GC
02.4

自動串接 6 大標準子資料夾的 package.path

SuperCode 會自動為工作區根目錄及 src/、lib/、modules/、core/、utils/ 配置 package.path（同時支援 ?.lua 與 ?/init.lua），無論是已儲存檔案或未存檔編輯器分頁皆可正確解析。

src/ · lib/ · modules/ · core/ · utils/ · ?/init.lua

智慧型 main.lua / init.lua 進入點仲裁

05 常見問答

常見問題

關於 Android 上 Lua 5.4 位元運算子、`<close>` 變數與跨資料夾 `require()` 的常見問題。

為什麼 `//` 和 `&` 在其他 Android Lua App 中會出現語法錯誤？+
許多舊款行動端 Lua App 仍採用停留在 Lua 5.2 的 Java 移植引擎 LuaJ，當時尚未引入 Lua 5.3/5.4 的原生 64 位元整數、`//` 整數除法與位元運算子。SuperCode 則是執行純正的原生 Lua 5.4.7。
不設定 `LUA_PATH` 的情況下，多檔案 `require()` 是如何運作的？+
SuperCode 會自動設定 `package.path`，同時搜尋專案根目錄以及 `src/`、`lib/`、`modules/`、`core/` 與 `utils/` 底下的 `?.lua` 和 `?/init.lua` — 甚至會在執行前同步未存檔的開啟分頁。
如果我在編輯 `lib/math_ext.lua`（而非 `main.lua`）時按下執行會怎樣？+
若目前檔案回傳模組資料表（`return M`）且專案根目錄存在 `main.lua` 或 `init.lua`，SuperCode 會自動執行進入點腳本，讓您不必來回切換分頁。
若區塊內拋出錯誤，Lua 5.4 的 `<close>` 還會正常觸發嗎？+
會的。與標準桌面版 Lua 5.4.7 完全一致，任何標記為 `<close>` 的區域變數，無論區塊正常結束或透過 `error()` 展開退回，都會確實呼叫其元資料表的 `__close(self, err)` 元方法。
