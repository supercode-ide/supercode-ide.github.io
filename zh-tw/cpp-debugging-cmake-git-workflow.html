02 核心能力

手機上的桌面級 C++20 工程開發體驗

02.1

跨標頭檔的精準 #line 1 實體行號對齊

無論是本機編譯或在雲端 C++ 整合多檔案 <thread> 專案，SuperCode 皆會注入標準 #line 指令，讓每個警告或範本錯誤直接跳轉至真實的 .cpp/.hpp 行號。

#line 1 指令 · 點擊跳轉錯誤雷達
02.2

針對 ::、-> 與 . 的離線 WASM AST 補全

完全離線觸發情境感知的 C++ 成員與命名空間自動補全——無需雲端延遲即可補全本機類別方法、結構欄位與 STL 符號。

WASM AST 引擎 · :: / -> / . 觸發
02.3

零損壞 C++ 語彙格式化 & 選取縮排

美化整份 C++20 檔案或指定函式區段，絕不破壞原生字串 R"(...)"、範本或註解，並提供基準縮排錨定與一鍵復原。

C++ 語彙格式化 · 局部選取安全
02.4

03 逐步操作流程

Android 上俐落的 C++20 除錯 & Git 發布流程

四個步驟即可提早攔截錯誤、統一排版風格，並提交通過驗證的 C++20 建置。

STEP 01 AST Error Radar

透過錯誤雷達即時攔截語法 & 括號問題

即時 Tree-sitter WASM 診斷會在輸入當下標記未閉合的範本、遺漏分號與拼寫錯誤。

STEP 02 CodeFormatEngine

編譯並 1:1 跳轉至任何編譯器診斷訊息

離線 GNU C++20 與 Unity 雲端 C++ 皆能跨多檔案標頭檔保留精準的 #line 檔案與行號。

STEP 03 #line 1 Mapper

暫存變更前先完成乾淨格式化

對已編輯檔案執行 SuperCode 一鍵 C++ 格式化，讓 PR 差異檢視保持清晰易讀。

STEP 04 Visual Git Diff

檢視統一差異 & 透過視覺化 Git 推送

在提交時光機逐行審查增刪內容、填寫提交訊息並推送至 GitHub 或 GitLab。

05 常見問答

常見問題

解答關於 C++20 多檔案編譯錯誤、AST 自動補全、C++ 格式化與 Git 整合的常見問題。

多檔案 C++ 編譯器錯誤會顯示精準的 .hpp 或 .cpp 檔名與行號嗎？+
會。離線 C++20 編譯器與 Unity 雲端 C++ 都會針對每個檔案輸出標準 #line 1 指令，使警告與錯誤能 1:1 對應回您本機精確的標頭檔或原始碼行號。
SuperCode 的 C++ 自動補全在沒有網路時也能運作嗎？+
可以。SuperCode 在裝置端運行 100% 離線的 Tree-sitter WASM AST 引擎，針對 ::、-> 與 . 觸發符號提供情境感知補全，完全零伺服器往返延遲。
C++ 格式化工具會破壞原生字串字面值或前置處理器指令嗎？+
不會。SuperCode 語彙感知 C++ 格式化工具能精確追蹤註解、字串/字元字面值與前置處理器行，支援局部選取格式化，並內建即時一鍵復原。
我可以不安裝 Termux 就直接把 C++ 專案提交並推送至 GitHub 嗎？+
可以。SuperCode 內建原生視覺化 Git 用戶端，支援 HTTPS 個人存取權杖（PAT）複製/拉取/推送、分支切換、彩色提交差異檢視及視覺化合併衝突解決器。
