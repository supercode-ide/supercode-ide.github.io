02 主要エンジニアリング機能

エンタープライズ級の鍵セキュリティと、モバイル回線切断でも壊れないファイル保存設計

移動中の 5G や Wi-Fi が瞬断しただけで本番の設定ファイルが「0バイト」に潰れてしまう一般的な FTP エディタの弱点を、プロトコルレベルで克服しました。

02.1

4大プロトコル完全網羅：SFTP・明示的 FTPS・暗黙的 FTPS・FTP

SSH SFTP（ポート22）、暗号化パッシブデータチャネル（PBSZ 0 + PROT P）対応の明示的 FTPS（TLS 1.2/1.3・ポート21）、暗黙的 FTPS（ポート990）、および標準 UTF-8 パッシブ FTP に対応しています。

SFTP (22) · FTPS TLS 1.3 (21) · FTPS (990) · FTP
02.2

SSH 秘密鍵ピッカー・AES-256 保管庫＆ TOFU ホスト鍵保護

OpenSSH、PEM、RSA、Ed25519、ECDSA 秘密鍵（.pem、.key、id_rsa、id_ed25519）とパスフレーズに対応。認証情報はすべて Android KeyStore AES-256-GCM でハードウェア暗号化され、SHA256 ホスト鍵の不一致警告で中間者攻撃（MITM）を防ぎます。

Ed25519 / RSA / PEM · AES-256-GCM · MITM ホスト鍵検証
02.3

3段階アトミック・リモート保存（0バイト破損を 100% 防止）

リモートファイルを開くと永続ローカルミラータブ（☁️）を生成。保存時は「一時ファイルへアップロード -> STAT/SIZE で正確なバイト数到達を検証 -> アトミックなリネーム上書き＋POSIX パーミッション維持」の3段階処理を実行します！

一時アップロード -> サイズ検証 -> アトミック置換 + chmod 維持
02.4

ライブ・ハンドシェイク診断コンソール＆自己修復コネクションプール

サーバー保存前に内蔵診断コンソールで TCP 接続、TLS/SSH ネゴシエーション、鍵認証をリアルタイム検証可能。さらに3チャネル多重接続プールが Wi-Fi と 5G の切り替え後も切断ソケットを自動復旧します。

⚡ ハンドシェイク診断 · 3チャネル自己修復プール
02.5

4並列ストリーム転送キュー＆バイト単位レジューム再開

ディレクトリツリー全体を4本の並列ストリームとリアルタイム MB/s 進捗パネルで高速に送受信。大容量転送が途中で切れても、SFTP RESUME や FTP REST により正確なバイトオフセットから再開できます！

4並列ストリーム · リアルタイム MB/s · バイト単位レジューム
02.6

リモート高速検索・Shift_JIS 等34文字コード＆ライブ Web プレビュー

リモートフォルダ横断のファイル名ファジー検索や、34文字コード指定での再読み込みに対応。さらにサーバー上の HTML/PHP ファイルで「実行」を押せば、編集前後のページをその場でライブプレビューできます。

03 実践ステップガイド

Android から本番サーバーへ安全に接続・編集する手順

ハードウェア暗号化保管庫に一度登録しておけば、外出先からでも数秒で安全な緊急パッチ適用が行えます。

STEP 01 Explorer -> Remote Servers -> +

プロトコルを選び、パスワードまたは SSH 秘密鍵を登録

SFTP、FTPS (TLS)、FTPS (990)、FTP から選択し、ホストとユーザー名を入力してパスワードまたは .pem / id_ed25519 秘密鍵ファイルを指定します。

STEP 02 ⚡ Test Handshake -> Save

ハンドシェイク診断と SHA256 ホスト指紋を確認して保存

「接続テスト」で TCP/TLS/SSH 認証をリアルタイム確認し、サーバーの SHA256 指紋を検証して AES-256 保管庫へ安全に保存します。

STEP 03 Mount -> Tap Remote File

AST 補完・自動整形フル装備でサーバー上のコードを編集

Nginx 設定、Python/PHP バックエンドコード、シェルスクリプトを直接タブで開き、AST 補完・エラーレーダー・1タップ整形を使って編集します。

STEP 04 Save / Batch Upload

3段階アトミック保存または競合制御付きフォルダ同期

保存タップで安全な3段階アトミック反映を実行。フォルダ複数選択での一括送受信（上書き・レジューム再開・両方維持・スキップ）にも対応します。

リモートの Linux POSIX ファイル権限（chmod）を完全維持 · アプリ再起動後もミラー作業を保持 入門ガイド

05 よくある質問

よくある質問 (FAQ)

AWS EC2 やレンタルサーバー・VPS の SSH 秘密鍵（.pem / Ed25519）、FTPS TLS 1.3、0バイト破損防止、レジューム転送に関する質問。

AWS EC2、ConoHa、さくら VPS、エックスサーバー等の Linux サーバーにはどの SSH 秘密鍵形式が使えますか？+
OpenSSH 形式、PEM（.pem）、RSA（id_rsa）、Ed25519（id_ed25519）、ECDSA の秘密鍵にパスフレーズ有無を問わず対応しており、Downloads や .ssh フォルダへ素早く移動できる専用キーピッカーを内蔵しています。
保存中にモバイル回線が切れても、サーバー上のファイルが 0バイトに壊れないのはなぜですか？+
すべてのリモート保存で「3段階アトミックトランザクション」を実行するためです。まず一時ファイルへアップロードし、STAT/SIZE コマンドで正確なバイト数が届いたことをサーバー側で検証できた場合にのみ、Linux 権限を維持したまま本番ファイルへアトミックにリネームします。
SSH の SFTP だけでなく、レンタルサーバー等でよく使われる FTPS（FTP over SSL/TLS）にも対応していますか？+
はい！ポート21で AUTH TLS 1.2/1.3 と暗号化パッシブデータチャネル（PROT P）を使う明示的 FTPS、ポート990の暗黙的 FTPS、そして標準の UTF-8 パッシブ FTP のすべてにネイティブ対応しています。
大きなバックアップのダウンロードやアップロードが途中で切れた場合、続きから再開できますか？+
はい。転送先に途中までのファイルが存在する場合、送信済みサイズを自動検知して1タップで正確なバイトオフセットからレジューム（再開）転送を行えます。
