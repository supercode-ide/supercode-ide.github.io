02 핵심 엔지니어링 기능

모바일 터치 환경을 위해 처음부터 다시 설계한 핵심 Git 워크플로

저장소 잠금 자동 복구, 미저장 탭 자동 플러시, Detached HEAD 구조 배너까지 갖춰 모바일 버전 관리의 실수를 원천 차단합니다.

02.1

택티컬 Git 대시보드 & 다중 저장소 원탭 전환기

마운트된 저장소, 활성 브랜치, 짧은 커밋 해시, 실시간 원격 ↑ Ahead / ↓ Behind 카운터, 수정/추가/삭제/충돌 파일 수를 한눈에 파악하고 여러 저장소를 원탭으로 전환합니다.

다중 저장소 전환 · ↑Ahead ↓Behind · 기존 폴더 마운트
02.2

HTTPS + PAT 클론 & 암호화 자격증명 영구 보관

개인 액세스 토큰(PAT)을 사용해 GitHub, GitLab, Gitee, Bitbucket 및 자체 호스팅 Git 서버의 공개·비공개 저장소를 클론하세요. 대상 폴더명이 자동으로 채워지며 토큰은 이후 푸시를 위해 안전하게 암호화 저장됩니다.

GitHub / GitLab / Gitee PAT · 실시간 전송 진행률
02.3

미저장 탭 자동 플러시, 변경 내역 미리보기 & 작성자 설정

커밋 실행 전 수정 중인 열린 에디터 탭을 디스크에 자동으로 먼저 저장하여 누락을 방지하며, 최대 80개 변경 파일을 [M]/[A]/[U]/[D] 배지로 미리 보여주고 커밋 작성자 이름·이메일 설정을 지원합니다.

편집 누락 제로 · 커스텀 작성자 · 업스트림 자동 바인딩
02.4

자동 Stash & 커서 위치 보존 핫 리로드를 갖춘 스마트 Pull

로컬에 아직 커밋하지 않은 수정본이 있을 때 Pull을 눌러도 걱정 없습니다. 불필요한 임시 커밋 없이 안전하게 자동 Stash 후 원격 변경분을 받고 로컬 작업을 복원한 뒤, 열린 탭을 원래 커서 줄·열 그대로 새로고침합니다!

무소음 자동 Stash · 커서 유지 인플레이스 탭 리로드
02.5

Git 타임머신, 브랜치 생성기 & 컬러 통합 Diff 뷰어

최대 120개의 커밋 히스토리를 탐색하며 모든 커밋의 2D 스크롤 +초록 / -빨강 통합 Diff를 확인하고, 로컬·원격 브랜치 생성 및 전환, 과거 스냅샷 안전 열람, 확인 절차가 포함된 하드 리셋을 수행합니다.

통합 Diff 뷰어 · + 새 브랜치 · Detached HEAD 원탭 복구

03 단계별 실전 사용법

완벽 6단계 가이드: SuperCode IDE에서 Git 사용하는 법

스마트폰이나 태블릿에서 클론, 브랜치 분기, 코드 비교, 충돌 병합, 원격 푸시까지 아래 순서대로 따라 해보세요.

STEP 01 메뉴 -> Git 제어 -> 클론

원격 저장소 클론 또는 로컬 프로젝트 마운트

HTTPS 주소(예: https://github.com/user/repo.git)와 선택적 PAT 토큰을 붙여넣고 클론을 탭하거나, 이미 .git 폴더가 있는 프로젝트라면 기존 저장소 마운트를 탭합니다.

STEP 02 타임머신 -> 브랜치 ▾

피처 브랜치 전환 또는 새 브랜치 생성

Git 타임머신을 열어 상단 브랜치 선택기로 브랜치를 바꾸거나, 브랜치명 유효성 검사가 적용된 + 새 브랜치 만들기…(예: feature/mobile-ui)를 탭합니다.

STEP 03 에디터 탭 -> 편집 / 저장

전체 IDE 인텔리전스로 다중 파일 코드 수정

오프라인에서 코드를 수정·정렬·테스트하세요. 실수로 열린 탭 저장을 깜빡하더라도 Git 명령 실행 직전 변경된 탭이 디스크에 자동 저장됩니다.

STEP 04 Git 대시보드 -> Pull

팀원의 원격 업데이트 안전하게 가져오기

푸시 전에 Pull을 탭하세요. 미커밋 로컬 수정본은 자동으로 Stash 후 복원되며, 열린 에디터 탭은 작업하던 커서 위치를 잃지 않고 즉시 갱신됩니다.

STEP 05 충돌 해결기 열기

겹치는 병합 충돌을 시각적 카드로 해결

동일 구간 수정 충돌이 발생하면 충돌 해결기 열기를 탭해 로컬 vs 원격 블록을 비교한 뒤 현재 유지 / 수신 유지 / 둘 다 유지를 선택하고 해결 적용을 누릅니다.

STEP 06 Commit & Push

대기 중인 파일 점검, 커밋 메시지 작성 & 푸시

대기 중인 변경 목록에서 [M]/[A]/[D] 배지를 확인하고 작성자 정보와 커밋 메시지를 입력한 뒤 COMMIT을 탭해 스테이징·커밋·원격 origin 푸시를 완료합니다.

비정상 종료 후 남은 index.lock 자동 복구 · 인터넷 없는 오프라인 로컬 커밋 완벽 지원 앱 가이드
04 기능 비교 매트릭스

SuperCode 비주얼 Git vs 타 안드로이드 Git 워크플로 비교

05 자주 묻는 질문

자주 묻는 질문 (FAQ)

GitHub 개인 액세스 토큰(PAT) 인증, 비공개 저장소 연동, 병합 충돌 해결 및 오프라인 커밋에 관한 실전 FAQ입니다.

GitHub, GitLab, Gitee의 비공개(Private) 저장소는 어떻게 인증하나요?+
GitHub/GitLab/Gitee에서 repo 권한이 부여된 HTTPS 개인 액세스 토큰(PAT)을 발급받아 클론, 커밋 & 푸시 또는 Pull 시 토큰 입력란에 붙여넣으세요. 암호화되어 안전하게 저장되므로 매번 다시 입력할 필요가 없습니다.
저장하지 않은 탭이나 아직 커밋하지 않은 수정 사항이 있는 상태에서 Pull을 누르면 어떻게 되나요?+
SuperCode가 먼저 미저장 탭을 디스크에 기록한 뒤 추적 중인 미커밋 변경분을 자동으로 Stash하고, 최신 원격 커밋을 받아 로컬 작업을 다시 적용한 다음 열린 탭을 정확한 커서 줄 위치 그대로 새로고침합니다.
이전 커밋에서 어떤 코드가 바뀌었는지 확인하거나 과거 시점으로 되돌리려면 어떻게 하나요?+
Git 대시보드에서 Git 타임머신을 열고 타임라인의 원하는 커밋을 탭하세요. 코드 변경 보기(Commit Diff)로 컬러 통합 Diff를 열람하거나, 체크아웃(읽기 전용)으로 스냅샷을 안전하게 살펴보고, 하드 리셋으로 브랜치를 되감을 수 있습니다.
인터넷 연결이 없는 오프라인 상태에서도 커밋할 수 있나요?+
네! 스테이징, 로컬 커밋 기록, 새 브랜치 생성, 커밋 히스토리 및 통합 Diff 열람, 병합 충돌 해결까지 모두 오프라인에서 작동하며, 나중에 네트워크에 연결되었을 때 원격 origin으로 한 번에 푸시할 수 있습니다.

안드로이드에서 저장소, Diff 비교, 병합까지 손끝으로 완벽히 제어하세요.
