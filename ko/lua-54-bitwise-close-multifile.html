02 핵심 엔지니어링 기능

Lua 5.3 & 5.4의 모든 최신 언어 기능을 오프라인에서

문법 오류 우회 없이 최신 표준 Lua 5.4 코드와 다중 디렉터리 패키지를 그대로 작성하세요.

02.1

네이티브 64비트 정수, // 나눗셈 & 비트 연산자

부동소수점 근사치가 아닌 정확한 64비트 부호 있는 정수를 기반으로 &, |, ~ (XOR/NOT), <<, >> 및 // 정수 몫 나눗셈을 사용해 비트마스크, 플래그, 해시, 타일 좌표를 직접 다루세요.

& | ~ << >> · // 정수 나눗셈 · 64비트 math.type()
02.2

컴파일 타임 <const> & 스코프 <close> 리소스 정리

<const>로 컴파일 타임 불변 지역 변수를 강제하고, <close>로 __close 메타메서드를 연결해 스코프 종료나 오류 발생 시 열린 파일, 잠금, SQLite 구문이 자동으로 해제되도록 합니다.

local x <const> · local f <close> · __close RAII
02.3

바이너리 string.pack / unpack & 내장 utf8

string.pack, string.unpack, string.packsize로 엔디안 지정자를 포함한 바이너리 구조체를 인코딩/디코딩하고, utf8.codes, utf8.len, utf8.char로 다국어 유니코드 문자열을 안전하게 순회하세요.

string.pack / unpack · utf8.codes · 세대별 GC
02.4

6개 표준 하위 폴더에 자동 연결되는 package.path

SuperCode가 워크스페이스 루트와 src/, lib/, modules/, core/, utils/ (?.lua 및 ?/init.lua 모두)에 package.path를 자동 설정하여, 저장된 파일은 물론 저장되지 않은 에디터 탭까지 바로 해석합니다.

05 자주 묻는 질문

자주 묻는 질문 (FAQ)

Android 환경에서의 Lua 5.4 비트 연산자, `<close>` 변수 및 다중 폴더 `require()`에 관한 자주 묻는 질문입니다.

다른 Android Lua 앱에서는 왜 `//`와 `&`에서 문법 오류가 발생하나요?+
많은 구형 모바일 Lua 앱은 Lua 5.3/5.4에서 네이티브 64비트 정수, `//` 정수 나눗셈, 비트 연산자가 도입되기 전인 Lua 5.2 시점에 멈춰 있는 Java 포팅 엔진인 LuaJ에 의존합니다. SuperCode는 정품 네이티브 Lua 5.4.7을 실행합니다.
`LUA_PATH`를 설정하지 않고 다중 파일 `require()`는 어떻게 작동하나요?+
SuperCode는 프로젝트 루트와 `src/`, `lib/`, `modules/`, `core/`, `utils/`에서 `?.lua`와 `?/init.lua`를 모두 검색하도록 `package.path`를 자동 구성하며, 실행 전 저장되지 않은 열린 탭까지 동기화합니다.
`main.lua` 대신 `lib/math_ext.lua`를 편집하는 중에 실행을 누르면 어떻게 되나요?+
현재 파일이 모듈 테이블(`return M`)을 반환하고 프로젝트 루트에 `main.lua` 또는 `init.lua`가 있으면 SuperCode가 진입 스크립트를 자동으로 실행하므로 탭을 번갈아 전환할 필요가 없습니다.
블록 내부에서 오류가 발생해도 Lua 5.4 `<close>`가 정상 작동하나요?+
네. 표준 데스크톱 Lua 5.4.7과 마찬가지로 `<close>`로 지정된 지역 변수는 블록이 정상 종료되든 `error()`로 예외가 풀리든 관계없이 메타테이블의 `__close(self, err)` 메타메서드를 확정적으로 호출합니다.
