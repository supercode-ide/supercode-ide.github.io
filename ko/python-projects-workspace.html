02 핵심 엔지니어링 기능

터치 환경에 맞게 재설계된 데스크톱급 Python 프로젝트 사용성

SuperCode의 Python 워크스페이스 리졸버는 모바일 파일 관리의 번거로움을 없애기 위해 세밀하게 설계되었습니다.

02.1

어느 열린 탭에서나 작동하는 스마트 엔트리 포인트 지정

최상위 실행 코드가 없는 `services/ledger.py`나 `models/user.py`를 편집 중이신가요? 실행을 탭하면 자동으로 프로젝트 루트(`pyproject.toml`, `requirements.txt`, `.git`)까지 탐색해 `main.py`, `app.py`, `run.py` 또는 `src/main.py`를 실행합니다.

헬퍼 모듈 편집 -> 실행 탭 -> main.py 실행
02.2

미저장 탭 실시간 메모리 오버레이 & PEP 420 네임스페이스

열려 있는 `.py` 탭 3개를 수정한 뒤 저장 없이 바로 실행하세요 — SuperCode가 미저장 에디터 버퍼를 메모리에 오버레이하며, `src/` 폴더에 불필요한 빈 `__init__.py` 파일을 채우지 않습니다.

대기 없는 즉시 실행 · PEP 420 암시적 네임스페이스 패키지
02.3

실제 대화형 input() & [EOF] 듀얼 패널 콘솔

연속적인 `input()`과 `sys.stdin.readline()` 호출이 있는 CLI 앱을 테스트하세요. 콘솔은 스마트폰에서는 코드 아래에 자동 도킹되고 태블릿에서는 55%/45% 좌우 분할되며 즉시 중지/인터럽트가 가능합니다.

논블로킹 Stdin 큐 · [EOF] 시그널 · 55:45 분할
02.4

오프라인 AST 자동 완성, PEP 8 포매터 & 에러 레이더

클래스와 모듈에서 `.`을 입력해 밀리초 미만의 오프라인 AST 자동 완성을 사용하고, 어지러운 들여쓰기를 원탭으로 PEP 8에 맞게 정리하며, 실행 전에 에러 레이더로 탭/공백 혼용(`TabError`)이나 누락된 콜론을 잡아내세요.

AST 스코프 엔진 · 원탭 PEP 8 · TabError 레이더
02.5

독립형 Visual Git & 120커밋 타임머신

HTTPS PAT로 비공개 GitHub/GitLab Python 리포지토리를 클론하고, 피처 브랜치를 생성하며, 구문 강조 Diff 확인, 시각적 병합 충돌 해결, 커밋 및 푸시까지 에디터를 벗어나지 않고 처리하세요.

03 단계별 실전 사용법

Android에서 Python 리포지토리 클론, 리팩토링, 테스트 및 푸시 방법

스마트폰이나 Android 태블릿에서 소프트웨어 엔지니어링의 전 과정을 완결하세요.

STEP 01 Git Clone / Open Folder

GitHub 리포지토리 클론 또는 로컬 프로젝트 트리 열기

HTTPS Personal Access Token으로 클론하거나 기기 저장소의 폴더를 여세요 — 스캔 시 `.git`, `venv`, `__pycache__` 같은 불필요한 폴더는 자동으로 제외됩니다.

STEP 02 Multi-Tab Edit + PEP 8

AST 자동 완성 & 21키 기호 바를 활용한 모듈 편집

21키 기호 바를 위로 스와이프해 `:`, `->`, `_`, `()`, `[]`, `INDENT`를 입력하고 포맷 버튼을 탭해 깔끔한 4칸 공백 PEP 8 정렬을 적용하세요.

STEP 03 Run ▶ / unittest

오프라인에서 엔트리 스크립트 또는 단위 테스트 스위트 실행

밀리초 단위의 즉각적인 실행 시간 측정 및 클릭 가능한 스택 트레이스 이동 기능과 함께 `main.py` 또는 `unittest` 스위트를 오프라인으로 실행하세요.

STEP 04 Git Time Machine -> Push

통합 Diff 검토, 커밋 & 업스트림 푸시

Git 타임머신에서 라인 단위 변경 사항을 검토하고 파일을 스테이징한 뒤 GitHub, GitLab 또는 Bitbucket으로 깔끔하게 푸시하세요.

05 자주 묻는 질문

자주 묻는 질문 (FAQ)

Android에서 Python의 `src/` 레이아웃, 상대 임포트, `unittest`, Git 연동에 대한 자주 묻는 질문입니다.

`utils/helpers.py` 같은 헬퍼 모듈을 편집하는 중에 실행 버튼을 누르면 어떻게 되나요?+
`helpers.py`에 최상위 실행 코드 없이 함수나 클래스만 정의되어 있다면, SuperCode가 자동으로 프로젝트의 엔트리 스크립트(`main.py`, `app.py`, `run.py`, `__main__.py` 또는 `src/main.py`)를 찾아 전체 애플리케이션을 실행합니다.
SuperCode는 `match/case` 및 `type` 별칭 같은 Python 3.12 문법을 지원하나요?+
구조적 `match/case`와 `tomllib`은 Python 3.11+에서 오프라인으로 동작하며, PEP 695 제네릭 `type` 별칭 문법을 사용하는 파일은 자동으로 Python 3.12 지원을 활성화합니다.
다중 폴더 임포트가 작동하려면 모든 폴더에 `__init__.py`가 있어야 하나요?+
아니요. SuperCode는 PEP 420 암시적 네임스페이스 패키지를 준수하므로 리포지토리에 불필요한 `__init__.py` 파일을 생성하지 않고도 프로젝트 루트를 깔끔하게 마운트합니다.
비공개 GitHub 리포지토리를 클론하고 Python 테스트를 오프라인으로 실행할 수 있나요?+
네. Visual Git에서 HTTPS + Personal Access Token으로 클론하고 `requirements.txt`를 한 번에 일괄 설치한 뒤 어디서나 완전 오프라인으로 `unittest` 스위트를 편집하고 실행할 수 있습니다.
