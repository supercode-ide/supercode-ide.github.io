02 ความสามารถหลัก

เขียนสคริปต์ JavaScript แบ็กเอนด์ & เครื่องมือจัดการไฟล์แบบไร้ความยุ่งยากของเทอร์มินัล

แปลงไฟล์ JSON/CSV อัตโนมัติ บีบอัดอาร์ติแฟกต์บิลด์ ทดสอบไลบรารีแบบโมดูลาร์ และรันยูทิลิตี้ CLI ออฟไลน์ได้ในระดับมิลลิวินาที

02.1

โมดูลหลัก Node.js ในตัวกว่า 29 โมดูลพร้อมใช้ออฟไลน์

นำเข้าโมดูลมาตรฐานแบบมีคำนำหน้า `node:` หรือชื่อตรงๆ โดยไม่ต้องตั้งค่าเพิ่ม: fs, fs/promises, path, path/posix, buffer, events, stream, stream/promises, stream/web, zlib, crypto, util, assert, url, querystring, readline, string_decoder, timers, timers/promises, perf_hooks, os, process และ diagnostics_channel

node:fs · path · buffer · events · stream · zlib · util
02.2

ซิงค์พื้นที่ทำงาน node:fs & fs/promises จริง

รัน readFileSync, writeFile, appendFile, mkdir({ recursive: true }), readdir, stat และ copyFile กับไฟล์โปรเจกต์จริงของคุณ บันเดิล JSON เอกสาร Markdown ไฟล์ CSV และไฟล์บีบอัด `.gz` ที่สร้างขึ้นจะปรากฏในโฟลเดอร์ Android ของคุณทันที

fs.readFileSync · fs/promises · I/O โฟลเดอร์ถาวร
02.3

ทำงานร่วมกันระหว่าง ES Modules (.mjs) & CommonJS (.cjs) ได้ไร้รอยต่อ

เขียน ES Modules สมัยใหม่ด้วย `import` / `export` และ top-level `await`, ดูแลยูทิลิตี้ CommonJS ด้วย `require()` และ `module.exports` และนำเข้าไฟล์ตั้งค่า `.json` ข้ามโฟลเดอร์ย่อยได้อย่างเป็นธรรมชาติ

import / export · require() · .mjs / .cjs / .json
02.4

รองรับ package.json Exports, Subpaths & #imports

จัดโครงสร้างแพ็กเกจหลายไฟล์ให้เป็นระเบียบด้วย `package.json`: SuperCode แยกเส้นทาง `\"type\": \"module\"`, `\"main\"`, แผนผัง `\"exports\"` แบบมีเงื่อนไข และการนำเข้าย่อย `#internal/*` — แม้แต่ข้ามแท็บเอดิเตอร์ที่ยังไม่ได้บันทึก

package.json · Conditional exports · นำเข้าย่อย #subpath
02.5

ไบนารี Buffer, EventEmitter, Streams & Zlib

ประมวลผลโปรโตคอลไบนารีและสตรีมข้อความขนาดใหญ่อย่างมีประสิทธิภาพบนมือถือด้วย `Buffer.alloc`/`concat` (UTF-8, hex, base64, base64url), `EventEmitter`, `Readable`/`Writable`/`Transform` `pipeline()` และ `zlib.gzipSync`/`gunzipSync`

Buffer · EventEmitter · stream.pipeline · gzipSync
02.6

สลับใช้ Cloud Node.js อัตโนมัติสำหรับ Sockets & Workers

เมื่อสคริปต์ของคุณต้องการตัวรับฟัง TCP/HTTP ระดับ OS หรือการแตกโปรเซสย่อย (`node:http`, `https`, `net`, `tls`, `dns`, `dgram`, `child_process`, `worker_threads`) SuperCode จะรวมโครงสร้างโมดูลในเครื่องส่งไปรันบน Cloud Node.js ให้อัตโนมัติ

http · net · worker_threads · แจ้งบรรทัดผิดพลาดตรง 1:1

03 ขั้นตอนการทำงาน

วิธีสร้างสคริปต์ Node.js หลายโมดูลบน Android

รันสคริปต์ระบบไฟล์ สตรีม และเครื่องมือ CLI จริงโดยไม่ต้องติดตั้งแพ็กเกจเทอร์มินัลขนาดหลายกิกะไบต์

STEP 01 package.json + src/

สร้างไฟล์ .js, .mjs หรือ .cjs ในพื้นที่ทำงานของคุณ

เริ่มสคริปต์เดี่ยวหรือเพิ่ม `package.json` พร้อม `\"type\": \"module\"` เพื่อเปิดใช้งานไวยากรณ์ ES Module ในไฟล์ `.js`

STEP 02 import fs from 'node:fs'

นำเข้า API หลัก Node.js ออฟไลน์ทั้ง 29+ รายการได้ทันที

อ่านไฟล์ `.json`/`.csv` ในเครื่อง จัดการพาธด้วย `node:path` แปลงข้อมูลสตรีม หรือบีบอัดผลลัพธ์ผ่าน `node:zlib`

STEP 03 Toolbar -> Run ▶

รันออฟไลน์ & โต้ตอบผ่าน node:readline

รันเสร็จในเสี้ยววินาทีภายในคอนโซลเวิร์กเกอร์ที่แยกอิสระ พร้อม stdin โต้ตอบสด `process.env` และผลทดสอบ `assert`

STEP 04 Explorer Sync + Git

ตรวจสอบไฟล์ที่เขียน & คอมมิตด้วย Visual Git

เปิดไฟล์ที่สร้างขึ้นได้ทันทีในเอดิเตอร์ของ SuperCode หรือคอมมิตแพ็กเกจ JavaScript แบบโมดูลาร์ขึ้น GitHub ด้วย Visual Git

โมดูลหลัก Node ออฟไลน์ 29+ รายการ · โอเวอร์เลย์โมดูลแท็บที่ยังไม่บันทึก · สลับ Cloud Node.js อัตโนมัติ คู่มือแอป

05 คำถามและคำตอบ

คำถามที่พบบ่อย

คำถามเกี่ยวกับโมดูล `node:*` ที่รองรับ, พาธไฟล์ `fs`, `package.json` และแพ็กเกจ npm บน Android

โมดูลหลัก Node.js ใดบ้างที่ทำงานแบบออฟไลน์ 100% ใน SuperCode?+
มีโมดูลมาตรฐานกว่า 29 รายการที่รันแบบออฟไลน์สมบูรณ์ ได้แก่ `fs`, `fs/promises`, `path`, `path/posix`, `buffer`, `events`, `stream`, `stream/promises`, `stream/web`, `zlib`, `crypto`, `readline`, `util`, `assert`, `url`, `querystring`, `string_decoder`, `timers`, `timers/promises`, `perf_hooks`, `os`, `process` และ `console`
`fs.writeFileSync('out.json', data)` จะบันทึกเป็นไฟล์จริงลงในโฟลเดอร์ Android ของฉันไหม?+
ใช่! การทำงานของระบบไฟล์จะอ่านจากโฟลเดอร์โปรเจกต์ที่เปิดอยู่โดยตรง (รวมถึงแท็บเอดิเตอร์ที่ยังไม่ได้บันทึก) และซิงโครไนซ์ทุกไฟล์ที่สร้างหรือแก้ไขกลับไปยังไดเรกทอรี Android ของคุณทันที
ฉันใช้ได้ทั้งคำนำหน้า `node:fs` และการเรียก `require('fs')` แบบปกติเลยไหม?+
ได้ ทั้งไวยากรณ์ ES Module สมัยใหม่อย่าง `import fs from 'node:fs/promises'` และการเรียก CommonJS แบบดั้งเดิมอย่าง `const fs = require('fs')` จะเชื่อมต่อไปยังตัวจัดการออฟไลน์ในตัวชุดเดียวกันทั้งหมด
จะเกิดอะไรขึ้นหากสคริปต์ของฉันนำเข้า `node:http`, `net` หรือ `worker_threads`?+
โมดูลที่ต้องใช้ซ็อกเก็ตเซิร์ฟเวอร์ระดับ OS หรือโปรเซสย่อย (`http`, `https`, `net`, `tls`, `dns`, `child_process`, `worker_threads`) จะถูกตรวจจับและส่งไปประมวลผลผ่านตัวบันเดิล Cloud Node.js แบบหลายไฟล์ของ SuperCode โดยอัตโนมัติ — ขณะที่การพรีวิว HTTP แบบฟูลสแตกในเครื่องก็ใช้งานได้ใน Web IDE ของ SuperCode เช่นกัน
