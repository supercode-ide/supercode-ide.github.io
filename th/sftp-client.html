02 ความสามารถหลัก

ความปลอดภัยระดับองค์กร & วิศวกรรมจัดการไฟล์ไร้ความเสียหาย

ออกแบบมาเพื่อเน็ตมือถือที่ไม่เสถียร — จุดที่ตัวแก้ FTP ทั่วไปมักตัดไฟล์ Config ระบบ Production เหลือ 0 ไบต์เมื่อ 5G หรือ Wi-Fi หลุด

02.1

ครบทั้ง 4 โปรโตคอล: SFTP, FTPS Explicit, FTPS Implicit & FTP

รองรับ SSH SFTP (พอร์ต 22), Explicit FTPS บน TLS 1.2/1.3 พร้อมช่องข้อมูลเข้ารหัส (PBSZ 0 + PROT P), Implicit FTPS (พอร์ต 990) และ passive FTP แบบ UTF-8 (พอร์ต 21)

SFTP (22) · FTPS TLS 1.3 (21) · FTPS (990) · FTP
02.2

ตัวเลือก SSH Private Key, คลัง AES-256 & ระบบป้องกัน TOFU

นำเข้าคีย์ OpenSSH, PEM, RSA, Ed25519 หรือ ECDSA (.pem, .key, id_rsa, id_ed25519) พร้อม Passphrase ข้อมูลลับทั้งหมดเข้ารหัสผ่าน Android KeyStore AES-256-GCM และแจ้งเตือนเมื่อ SHA256 Host-Key ไม่ตรงกัน

Ed25519 / RSA / PEM · AES-256-GCM · ป้องกัน MITM Host
02.3

Atomic Remote Save 3 ขั้นตอน (หมดปัญหาไฟล์เสีย 0-Byte)

การเปิดไฟล์ Remote จะสร้างแท็บจำลองในเครื่อง (☁️) เมื่อกดบันทึกจะอัปโหลดเป็นไฟล์ชั่วคราว ตรวจขนาดไบต์ปลายทางด้วย STAT/SIZE แล้วเปลี่ยนชื่อทับแบบ Atomic พร้อมคงสิทธิ์ POSIX ไว้เหมือนเดิม!

อัปไฟล์ชั่วคราว -> เช็กขนาด -> เปลี่ยนชื่อ Atomic + chmod
02.4

คอนโซลทดสอบ Handshake สด & Connection Pool ฟื้นตัวอัตโนมัติ

ตรวจสอบ TCP, การเจรจา TLS/SSH และ Key Auth ในคอนโซลวินิจฉัยก่อนบันทึกเซิร์ฟเวอร์ พร้อม Connection Pool 3 ช่องที่กู้คืน Socket ค้างอัตโนมัติเมื่อสลับ Wi-Fi/5G

⚡ ทดสอบ Handshake · Pool 3 ช่องฟื้นตัวอัตโนมัติ
02.5

คิวโอนไฟล์ 4 สตรีม & ทำต่อจาก Byte-Offset เดิม

อัปโหลดหรือดาวน์โหลดทั้งโครงสร้างโฟลเดอร์ผ่าน 4 สตรีมคู่ขนานพร้อมแผงวัดความเร็ว MB/s แบบ 20fps ไฟล์ใหญ่ที่ขาดกลางคันสามารถทำต่อจากจุด Byte เดิมได้ด้วย SFTP RESUME หรือ FTP REST!

4 สตรีมคู่ขนาน · MB/s สด · ทำต่อตรง Byte-Offset เดิม
02.6

ค้นหาชื่อไฟล์ Remote แบบ Fuzzy & พรีวิวเว็บสดจากเซิร์ฟเวอร์

ค้นหาไฟล์ในโฟลเดอร์เซิร์ฟเวอร์ Remote โหลดแท็บใหม่ได้ด้วย Encoding กว่า 34 รูปแบบ และกด Run บนไฟล์ HTML/PHP ระยะไกลเพื่อพรีวิวหน้าเว็บจริงก่อนหรือหลังแก้ไข

ค้นหา Fuzzy ระยะไกล · 34 Encodings · พรีวิวเว็บสด
ออกแบบเพื่อมือถือ จอพับ และแท็บเล็ต · ขนาดเบา 40.2 MB ภาพรวม
03 ขั้นตอนการทำงาน

วิธีเชื่อมต่อและแก้ไขเซิร์ฟเวอร์จริงอย่างปลอดภัยจาก Android

ตั้งค่าครั้งเดียวในคลังเข้ารหัสระดับฮาร์ดแวร์ แล้วส่ง Hotfix ได้จากทุกที่ในไม่กี่วินาที

STEP 01 Explorer -> Remote Servers -> +

เลือกโปรโตคอล & ใส่รหัสผ่านหรือนำเข้า SSH Key

เลือก SFTP, FTPS (TLS), FTPS (990) หรือ FTP กรอก Host/User แล้วกรอกรหัสผ่านหรือเลือกไฟล์ Private Key (.pem / id_ed25519)

STEP 02 ⚡ Test Handshake -> Save

ตรวจผล Handshake & เชื่อถือ Host Fingerprint

แตะ Test Handshake เพื่อยืนยัน TCP/TLS/SSH แบบเรียลไทม์ ตรวจสอบ SHA256 Host Fingerprint ของเซิร์ฟเวอร์ แล้วบันทึกลงคลัง AES-256

STEP 03 Mount -> Tap Remote File

เปิดดูโครงสร้าง Remote & แก้โค้ดด้วย AST + จัดฟอร์แมตครบชุด

เปิดไฟล์ Config Nginx, ไฟล์แบ็กเอนด์ Python/PHP หรือ Shell สคริปต์ในแท็บตัวแก้ไขได้ทันที พร้อม AST Completion, Error Radar และจัดฟอร์แมตในแตะเดียว

STEP 04 Save / Batch Upload

บันทึกแบบ Atomic หรือซิงก์โฟลเดอร์พร้อมคุมไฟล์ชนกัน

แตะ Save เพื่ออัปเดตแบบ Atomic 3 ขั้นตอน หรือเลือกหลายโฟลเดอร์เพื่ออัปโหลด/ดาวน์โหลดโดยเลือกนโยบาย Overwrite, Byte-Offset Resume, Keep Both หรือ Skip ได้เลย

คงสิทธิ์ไฟล์ POSIX บน Linux ปลายทาง · ข้อมูลอยู่ครบแม้รีสตาร์ทแอปแบบออฟไลน์ คู่มือแอป
04 ตารางเปรียบเทียบความสามารถ

SuperCode SFTP / FTPS Workspace เทียบกับแอปโอนไฟล์แยกทั่วไป

SuperCode SFTP & FTPS Client คือตัวแก้โค้ดเซิร์ฟเวอร์ Remote ในตัวสำหรับ Android รองรับ SFTP (SSH), Explicit/Implicit FTPS (TLS 1.3) และ FTP ผสานคลังเก็บ SSH Key แบบ Android KeyStore AES-256, ตรวจ Fingerprint แบบ TOFU, บันทึกไฟล์ Remote แบบ Atomic 3 ขั้นตอน และรับส่งไฟล์ต่อจาก Byte เดิมแบบ 4 สตรีม

ตารางเปรียบเทียบการแก้โค้ด REMOTE ผ่าน SFTP / FTPS บน ANDROID
ความสามารถด้าน Remote SuperCode SFTP/FTPS Studio แอปโอนไฟล์ FTP ทั่วไป ปลั๊กอิน Editor พื้นฐาน
โปรโตคอลที่รองรับ SFTP (22) + FTPS Explicit TLS 1.3 + FTPS 990 + FTP โอนไฟล์อย่างเดียว (ไม่มี IDE) รองรับแค่ FTP/SFTP พื้นฐาน
ความปลอดภัยคีย์ & MITM Ed25519/RSA/PEM + AES-256 KeyStore + TOFU SHA256 ไม่แน่นอน; ไม่มี AST Editor เก็บเป็น Plaintext หรือคีย์อ่อนแอ
ความปลอดภัยเมื่อเน็ตหลุดขณะบันทึก Atomic Save 3 ขั้นตอน + คงสิทธิ์ POSIX เดิม ต้องโหลดมาแก้แล้วอัปขึ้นใหม่เอง สตรีมตรงเสี่ยงไฟล์เหลือ 0-byte
การโอนไฟล์ที่ขาดกลางคัน 4 สตรีมคู่ขนาน + โหลดต่อตรง Byte-Offset เดิม ต้องจ่ายเงินซื้อเพิ่มในบางแอป ต้องเริ่มใหม่จาก 0%

05 คำถามและคำตอบ

คำถามที่พบบ่อย

คำตอบเรื่อง SSH Private Key (.pem / Ed25519), FTPS TLS 1.3, การป้องกันไฟล์ Remote เสียหาย และการโหลดไฟล์ใหญ่ต่อจากจุดเดิม

รองรับ SSH Private Key แบบใดบ้างสำหรับ AWS EC2, DigitalOcean หรือ Linux VPS?+
SuperCode รองรับคีย์ OpenSSH, PEM (.pem), RSA (id_rsa), Ed25519 (id_ed25519) และ ECDSA ทั้งแบบมีและไม่มี Passphrase พร้อมตัวเลือกเปิดหาโฟลเดอร์ Downloads และ .ssh ได้ทันใจ
SuperCode ป้องกันไฟล์ 0-byte เสียหายบนเซิร์ฟเวอร์เมื่อสัญญาณมือถือหลุดขณะบันทึกอย่างไร?+
ทุกการบันทึกแท็บ Remote ใช้ธุรกรรม Atomic 3 ขั้นตอน: อัปโหลดไปยังไฟล์ชั่วคราวก่อน ตรวจนับขนาดไบต์บนเซิร์ฟเวอร์ผ่าน STAT/SIZE ว่าครบถ้วน แล้วจึงเปลี่ยนชื่อทับไฟล์เป้าหมายแบบ Atomic พร้อมรักษาสิทธิ์ POSIX บน Linux ไว้ครบถ้วน
SuperCode รองรับ FTPS (FTP ผ่าน SSL/TLS) นอกเหนือจาก SSH SFTP หรือไม่?+
รองรับ! ทั้ง Explicit FTPS (AUTH TLS 1.2/1.3 บนพอร์ต 21 พร้อมช่องข้อมูลแบบเข้ารหัส PROT P) และ Implicit FTPS (พอร์ต 990) รวมถึง passive FTP แบบ UTF-8 มาตรฐานในตัว
สามารถดาวน์โหลดหรืออัปโหลดไฟล์ Backup ขนาดใหญ่ต่อได้ไหมหากเน็ตหลุดกลางคัน?+
ได้ เมื่อโอนไฟล์ชนกับไฟล์ที่ค้างอยู่บางส่วน SuperCode จะตรวจขนาดที่โอนแล้วและให้กด Resume Partial Transfer เพื่อทำต่อจาก Byte-Offset เดิมในแตะเดียวโดยไม่ต้องส่งซ้ำ
