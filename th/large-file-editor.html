02 ความสามารถหลัก

สร้างมาเพื่อจัดการ Production Log, Database Dump และรหัสอักขระแบบดั้งเดิม

การป้องกันหน่วยความจำหลายระดับช่วยให้การเลื่อน ค้นหา และบันทึกยังคงตอบสนองไว แม้เป็นไฟล์ JSON บรรทัดเดียวขนาดมหึมาหรือ Server Log หลาย GB

02.1

แบ่งหน้าสตรีมบนดิสก์ 10MB อัตโนมัติสำหรับไฟล์ระดับ GB

ไฟล์ที่มีขนาดเกิน 30 MB จะเปิดใช้งานตัวแบ่งหน้าแบบสตรีมบน I/O พื้นหลังอัตโนมัติ — ตัดแบ่ง Log, CSV และไฟล์สำรอง SQL ขนาดยักษ์เป็นหน้าละ 10,000,000 ตัวอักษร พร้อมรองรับบรรทัด Minified ที่ยาวกว่า 4,000 ตัวอักษรโดยไม่หน่วง

10M ตัวอักษร/หน้า · ลื่น 120Hz · ปลอดภัยกับบรรทัด Minified
02.2

ศูนย์ควบคุม Mega-File & การรวมบันทึกแบบ Atomic

นำทางด้วยปุ่มหน้าก่อนหน้า, หน้าถัดไป หรือกระโดดไปหน้า 1..N โดยตรง (เขียนเก็บการแก้ไขในหน้าปัจจุบันอัตโนมัติ) แล้วแตะรวมทั้งหมดและบันทึก (Merge All & Save) เพื่อประกอบไฟล์ GB คืนบนดิสก์แบบ Atomic

ข้ามหน้า [1/N] · บันทึกหน้าแก้ไขอัตโนมัติ · บันทึกแบบ Atomic
02.3

แทนที่แบบสตรีมทั้งไฟล์ & กลุ่มจับคู่ Regex

สั่ง Global Stream Replace All ข้ามทุกหน้าบนดิสก์โดยไม่ต้องโหลดทั้งไฟล์ลง RAM รองรับกลุ่มจับคู่ $1..$99 และ ${name}, อักขระหลีก \n/\t, การค้นหาเฉพาะส่วนที่เลือก และฟิวส์ตัดเวลา Regex 1,200ms

Stream Replace All · Regex $1..$99 · บัฟเฟอร์ผลลัพธ์ 50,000+ จุด
02.4

คลิปบอร์ดเสมือนขนาดยักษ์ 15 MB (100k+ บรรทัด)

คลิปบอร์ดระบบของ Android มักล้มเหลวที่ราว 800 KB คลิปบอร์ดเสมือนในโปรเซสของ SuperCode ให้คุณคัดลอก ตัด และวางแบบสตรีมข้ามแท็บได้สูงสุด 15 MB สำหรับ Log หรือคำสั่ง SQL ได้สบายๆ

ก้าวข้ามขีดจำกัด OS 800 KB · วางได้สูงสุด 15 MB
02.5

34 รหัสอักขระ & ระบบป้องกันข้อมูลเพี้ยนก่อนบันทึก

ตรวจจับอัตโนมัติ 5 ขั้นตอนครอบคลุม UTF-8/16/32, GB18030/GBK/Big5, Shift_JIS/EUC-JP, EUC-KR, KOI8-R, ISO-8859 ทั้ง 11 ชุด และ Windows code pages อีก 9 ชุด พร้อมเตือนเมื่อพบอักขระ Unicode ที่แปลงไม่ได้ก่อนบันทึกเพื่อไม่ให้ข้อความกลายเป็น ?

34 ชุดอักขระ · ลบ BOM อย่างปลอดภัย · LF / CRLF / CR
02.6

ค้นหาแบบ Fuzzy ในเวิร์กสเปซ 50k ไฟล์ & ไฟร์วอลล์ไฟล์ไบนารี

ค้นหาไฟล์ใดก็ได้ในเวิร์กสเปซ Local, Git, SD/USB OTG และ SFTP ด้วยการจัดอันดับ CamelCase/เส้นทาง 7 ระดับ (ตัด node_modules/.git อัตโนมัติ) พร้อมระบบตรวจ Magic-Byte 4 KB บล็อกไฟล์ไบนารีดิบอย่างปลอดภัย

50k โหนด · รองรับ USB OTG · ป้องกัน Magic-Byte 4 KB
ออกแบบเพื่อมือถือ จอพับ และแท็บเล็ต · ขนาดเบา 40.2 MB ภาพรวม
03 ขั้นตอนการทำงาน

วิธีตรวจสอบและแก้ไขไฟล์หลายร้อย MB หรือระดับ GB แบบเป็นชุด

แก้ไขไฟล์ Log ขนาดมหึมา, ไฟล์ส่งออก CSV และไฟล์รหัสอักขระเดิมได้อย่างปลอดภัยบนมือถือหรือแท็บเล็ต Android ทุกรุ่น

STEP 01 Internal / SD / USB OTG

เปิดไฟล์ Log, CSV หรือ SQL Dump ขนาดยักษ์ใดก็ได้

เลือกไฟล์จากหน่วยความจำภายในหรือการ์ด SD/ไดรฟ์ USB OTG ที่เชื่อมต่ออยู่ SuperCode จะตรวจจับรหัสอักขระอัตโนมัติและแบ่งหน้า 10M ตัวอักษรขึ้นมาทันที

STEP 02 Page [1/N] Cockpit

ข้ามไปยังส่วนหน้าที่ต้องการได้โดยตรง

แตะปุ่ม Page บนแถบเครื่องมือ Mega-File 7 ปุ่มที่กระชับเพื่อข้ามไปยังหมายเลขหน้า สลับโหมดข้อความ หรือเข้าสู่ Zen Mode ไร้สิ่งรบกวน

STEP 03 Search / Stream Replace

ค้นหาหรือรัน Global Stream Replace All

ย่อแถบค้นหาเป็นมินิแคปซูลลอยตัวขณะไล่ดูผลลัพธ์ หรือเรียกใช้ Global Stream Replace All เพื่อแปลงรูปแบบข้อความข้ามทุกหน้าบนดิสก์

STEP 04 Merge All & Save

บันทึกการเปลี่ยนแปลงลงดิสก์แบบ Atomic

แตะ Merge All & Save เพื่อเขียนส่วนที่แก้ไขทั้งหมดกลับไปยังไฟล์ต้นฉบับอย่างปลอดภัย พร้อมคงความสมบูรณ์ของรหัสอักขระไว้ครบถ้วน

รองรับหน่วยความจำภายใน, การ์ด SD ภายนอก และไดรฟ์ USB OTG แบบเสียบใช้งานทันที คู่มือแอป
04 ตารางเปรียบเทียบความสามารถ

เกณฑ์ประสิทธิภาพไฟล์ใหญ่ & การเข้ารหัสอักขระบน Android

ตัวแก้ไขไฟล์ขนาดใหญ่ของ SuperCode ช่วยให้ผู้ใช้ Android เปิดไฟล์ข้อความ, Log, CSV และ SQL ขนาดหลายร้อย MB ถึงระดับกิกะไบต์ได้ทันทีโดยไม่ค้าง ผสานระบบแบ่งหน้าบนดิสก์ 10M ตัวอักษร, การค้นหาและแทนที่ด้วย Regex แบบสตรีมทั้งไฟล์, คลิปบอร์ดเสมือน 15 MB และการตรวจจับรหัสอักขระอัตโนมัติ 34 รูปแบบโดยไม่สูญเสียข้อมูล

ตารางเปรียบเทียบเอนจินไฟล์ข้อความขนาดใหญ่ & รหัสอักขระ · ANDROID
ความสามารถ เอนจิน Mega-File ของ SuperCode ตัวแก้ไขโค้ดทั่วไป ตัวเปิดไฟล์ของระบบ
ไฟล์ 500 MB – 2 GB+ แบ่งหน้าบนดิสก์ 10MB ทันที + ข้ามหน้า 1..N เด้งเพราะ RAM เต็มทันทีที่เปิด ปฏิเสธการเปิด (>2 MB–10 MB)
ค้นหา & แทนที่ทั้งไฟล์ แทนที่ทั้งหมดแบบสตรีมบนดิสก์ + กลุ่ม Regex $1..$99 แทนที่ได้เฉพาะใน RAM เท่านั้น อ่านอย่างเดียวหรือไม่มีฟังก์ชันแทนที่
ไฟล์บรรทัดเดียวแบบ Minified โหมดแสดงผลพื้นฐานอัตโนมัติ (>4,000 ตัวอักษร) · ไม่ค้าง 0% UI ค้างเมื่อเจอ JS/JSON แบบ Minified ค้างระหว่างตัดบรรทัด (Word Wrap)

การเข้ารหัสแบบดั้งเดิม (Legacy) 34 ชุดอักขระ (GB18030, Shift_JIS, EUC-KR, Win-125x) + ตัวป้องกัน UTF-8 รองรับเฉพาะ UTF-8 (ตัวอักษร CJK/Cyrillic เพี้ยน) ไม่มีตัวเลือกเปลี่ยนรหัสอักขระ

05 คำถามและคำตอบ

คำถามที่พบบ่อย

คำถามที่พบบ่อยเกี่ยวกับการเปิดไฟล์ระดับ GB, การแทนที่ด้วย Regex, แฟลชไดรฟ์ USB และการแก้ปัญหาตัวอักษร CJK/รหัสเดิมเพี้ยน

มือถือ Android แก้ไขไฟล์ขนาด 1 GB โดยไม่ให้ RAM เต็มได้อย่างไร?+
แทนที่จะโหลดข้อมูลทั้งกิกะไบต์เข้าสู่หน่วยความจำ SuperCode จะสตรีมไฟล์แบ่งเป็นส่วน (Chunk) บนดิสก์หน้าละ 10,000,000 ตัวอักษร (~10 MB) โดยโหลดเฉพาะหน้าที่เปิดดูอยู่ และระบบ Global Stream Replace จะประมวลผลทีละส่วนบนดิสก์ตามลำดับ
SuperCode แก้ปัญหาไฟล์ข้อความภาษาจีน ญี่ปุ่น เกาหลี หรือรัสเซียที่แสดงผลเพี้ยนได้ไหม?+
ได้ ระบบตรวจจับรหัสอักขระ 5 ขั้นตอนสามารถระบุได้ถึง 34 ชุดอักขระ รวมถึง GB18030, GBK, Big5, Shift_JIS, EUC-JP, EUC-KR, KOI8-R, Windows-1251/1252 และ UTF-16 แบบไม่มี BOM พร้อมให้โหลดใหม่หรือแปลงเป็น UTF-8 ได้โดยไม่เสียข้อมูล
จะเกิดอะไรขึ้นหากไฟล์มีโค้ด JSON หรือ JS แบบ Minified ยาว 500 KB ในบรรทัดเดียว?+
บรรทัดที่ยาวเกิน 4,000 ตัวอักษรจะสลับเข้าสู่โหมดแสดงผลพื้นฐานความเร็วสูง O(1) โดยปิดการตัดคำอัตโนมัติ เพื่อให้เลื่อนดูไฟล์บันเดิลแบบ Minified และไฟล์ Log ได้ลื่นไหลไม่มีสะดุด
เปิดไฟล์ขนาดใหญ่โดยตรงจากแฟลชไดรฟ์ USB หรือการ์ด SD ได้ไหม?+
ได้ SuperCode รองรับทั้งหน่วยความจำภายใน การ์ด SD ภายนอก และไดรฟ์ USB OTG แบบเสียบใช้งานได้ทันทีผ่าน Workspace Explorer

เปิดไฟล์ Log, Dump ขนาดยักษ์ และไฟล์รหัสเดิมได้ไม่มีเด้ง
